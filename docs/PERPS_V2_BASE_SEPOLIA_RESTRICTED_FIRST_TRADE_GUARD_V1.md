## Proposed closed test and local guard

The buyer is the canonical **short** `0x66858286fEEA78a05eA093673EA1535E0A52002d` (current market-1 size **−1,000,000** in 1e8 units); the seller is the canonical **long** `0xff287410852B9328437eaC353720e5476bC5F837` (size **+1,000,000**). The later exact size, execution price, nonzero finite deadline, bounds, maker flag, intent ID, signatures, nonce and fee envelope require independent operator review. No live payload or deadline was created here. Availability and exclusive control of the two trader signing accounts remain prerequisites; no trader key was accessed.

[`restricted_first_trade_guard.py`](../tools/perps_v2_cutover/restricted_first_trade_guard.py) is validation-only and supplies **no wallet, RPC sender, backend worker or command that broadcasts**. It binds the SHA-256 of a future reviewed package to chain 84532, PME and recovery Engine addresses, Engine runtime Keccak, one executor, zero ETH, exact typed transaction envelope and canonical ABI calldata. It decodes and re-encodes the complete 12-field `PerpTrade` plus both 65-byte signatures; rejects other selectors, malformed offsets/padding and trailing bytes; checks the reused PME EIP-712 domain, exact digest and both recovered signers using Ethereum Keccak and canonical low-s ECDSA. It requires current trader nonces, a fresh nonzero intent ID, bounded future deadline (at most 900 seconds from the pinned live block), positive bilateral price bounds, and close-only live positions. It requires PME to point to NEW_ENGINE, that Engine's runtime identity and SEALED state, all necessary authorization/release flags, and exactly the selected runtime executor as the active on-chain executor set. The package hash prevents silent changes to price, size, bounds, deadline, maker flag, traders, calldata or fee fields after approval.

The exact approved gas limit, EIP-1559 caps, local L1-fee allowance, total planning budget and live executor balance are also checked. The L1 allowance is a **local pre-send guard**, not an on-chain maximum fee guarantee. The one-shot integration primitive requires an owner-controlled private journal directory, exclusive file lock and fsynced, mode-0600 journal. It records the reviewed package identity, calldata hash, intended transaction hash/nonce and `SUBMISSION_UNKNOWN` **before** invoking an injected callback. A callback timeout or error leaves that state for manual receipt/nonce reconciliation; it cannot auto-retry. A successful callback changes the journal to `SUBMITTED`, not `CONFIRMED`; only a later canonical receipt and economic readback can establish execution. No callback capable of signing or sending is supplied. Journal persistence failure prevents callback invocation. Synthetic tests cover repeated attempts, ambiguity and persistence failure.

**Integration boundary:** the current guard takes a caller-supplied pinned `live` snapshot and candidate transaction; it does not itself authenticate an RPC response or prove a signed raw transaction encodes that candidate. A later first-trade package must add a trusted live-state collector and independently decode/compare the signed raw transaction (including `to`, chain, nonce, value, calldata, gas and fee fields) before connecting any sender. It must pin/refresh the executor inventory and block state immediately before the send, and record an exact transaction hash. Until that integration and signer isolation are tested, synthetic acceptance is not live readiness.

On chain, the PME limits *who* can invoke all three execution entrypoints and verifies signatures/nonces/expiry; it has **no trader allowlist**. The local guard limits only what a cooperating controlled sender would submit. A holder of the runtime executor key could call the PME directly and bypass this local helper. The local backend is stopped, but that does not prove no other program holds the executor signer. Source inspection of `deopt-v2-backend/src/main.rs:251-304` and `src/execution/broadcast_runtime.rs:330-489` shows that arming the normal real-broadcast runtime starts a recurring pending-intent batch worker; it is unsuitable as the sole one-shot safeguard. `src/execution/config.rs:488-526` checks a LocalKeystore signer against the configured executor address at startup but does not enforce exclusive access to that keystore. No secret value, keystore, live signature or historical DB payload was read for this milestone. Signer custody/access inventory remains a concrete separate review gate.
