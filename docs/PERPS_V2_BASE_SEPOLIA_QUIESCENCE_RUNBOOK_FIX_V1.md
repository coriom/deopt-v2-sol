## 1. Fixture identity strategy (durable, structural — not timestamp-alone)

The fixture generator triple in `tests/perps_broadcast_durability_pg_integration.rs` produces two distinctive structural markers that survive future test-DB pollution regardless of `created_at_ms`:

**Intent-side marker** — `(buyer, seller)` pair encoded by `addr(0x11) / addr(0x12)`:

```rust
fn addr(seed: u8) -> AccountId {
    let mut bytes = [0u8; 20];
    bytes[0] = seed;
    for (i, b) in bytes.iter_mut().enumerate().skip(1) {
        *b = (i as u8).wrapping_mul(seed).wrapping_add(0x1f);
    }
    // hex(bytes)
}
```

- `addr(0x11)` = `0x1130415263748596a7b8c9daebfc0d1e2f405162`
- `addr(0x12)` = `0x1231435567798b9dafc1d3e5f7091b2d3f516375`

These are collectively hand-picked deterministic outputs. No real signer/matching engine would ever produce this exact buyer/seller pair. Predicate:

```sql
NOT (buyer  = '0x1130415263748596a7b8c9daebfc0d1e2f405162'
 AND  seller = '0x1231435567798b9dafc1d3e5f7091b2d3f516375')
```

**Broadcast-side marker** — the sentinel `raw_tx_hex` values `'0x02f8...deadbeef'` (17 chars) and `'0x02f8...cafe'` (13 chars), both from `make_record()` and its cross-version variant in `tests/perps_broadcast_durability_pg_integration.rs`. Real EIP-1559 envelopes signed by the runtime executor are 1522–1650 characters (e.g., 1522 for `81457da4-b17a`'s real broadcast). The distinguishing structural property is length:

```sql
LENGTH(raw_tx_hex) >= 20
```

This holds for every real broadcast and fails for every fixture sentinel. **Documented schema limitation**: the DB does not carry a first-class `is_fixture` column or `test_seed` marker on `execution_intents` / `execution_intent_broadcasts`. Adding one would require a migration (out of scope; see §7). The structural predicates above are the operator's next-best durable approximation and provably fully partition the fixture population (verified via cross-check with the `created_at_ms=1_700_000_000_000` proxy — both partitions yield identical row sets today).

## 7. Documented schema limitation

The DB lacks a first-class `is_fixture` / `test_seed` marker column on `execution_intents` and `execution_intent_broadcasts`. The structural fixture predicates in §1 rely on hex-encoded outputs of the test-fixture address-generator (`addr(0x11)`, `addr(0x12)`) and the sentinel `raw_tx_hex` length boundary. This is durable across future runs of the same test binary (the outputs are deterministic) but is not migration-hardened against a hypothetical future test module using different seeds or different sentinels.

Adding a proper `is_fixture BOOLEAN NOT NULL DEFAULT false` column on both tables would tighten the quiescence gate long-term. This is out of scope for the runbook-fix milestone but a candidate migration for post-cutover backlog: `PERPS_V2_BACKEND_FIXTURE_MARKER_MIGRATION_V1`.
