## Contract semantics

Frozen `PerpRiskModule.setMaxOracleDelay(uint256)` is `onlyOwner` and rejects values above 3,600. `maxOracleDelay()` is the storage-backed getter. The value is seconds. Constructor default zero causes `_isOracleDataFresh` to return true without the additional Risk age check. At 600, age 599 and 600 are accepted and age 601 is rejected. This is a governance workflow defect; there is no Solidity patch in this milestone.

C20 targets predicted D5 `0x90CAA6D5bC628577bc76d6Cc8b775f983c75e110` with `setMaxOracleDelay(600)`. C12 targets canonical D4 `0xd0901DE8f6de72aecC716CA1465C4Cf58a0B99fB` with `setRiskModule(D5)`. The deployed ProtocolTimelock `0xa67f8E8E673ce4bb2Fb563B0e6E9FA8F70E3b588` reported `minDelay() = 86400` seconds at Base Sepolia block 47,883,802. The gate re-reads `minDelay()` at the future queue block; it does not freeze that observation as a future delay.

Run the same gate with `--phase execution`, supplying both the prior `c12AuthorizationReadback` result and a `c12Queue` evidence object, immediately before any separate public C12 execution. This phase checks that the prior readback block was canonical and between C20 execution and C12 queue, re-reads Risk delay at that earlier block, verifies C12's own queue receipt/event, and re-reads all live protections. A failed check stops; do not auto-fix or auto-schedule C20.

The validator uses only read-only RPC methods. It checks chain 84532, canonical D4/D5 deployment receipts, D5 creation input and runtime, D5 Timelock ownership and D4 pointer, exact C20 Timelock calls/events, public receipt status, operation ID and queue state, current D5 delay 600, and absence of any later `MaxOracleDelaySet` event. It rejects DelegateCall/MultiSend and any receipt containing more than one Timelock operation. It requires D4 Risk pointer zero, migration OPEN, all four D4 emergency restrictions active, D4 unauthorized in Vault and Insurance, PME absent or paused, and a local backend stop check. It rejects C12 already queued at authorization, early or batch-style C12 scheduling, and stale or inconsistent evidence.
