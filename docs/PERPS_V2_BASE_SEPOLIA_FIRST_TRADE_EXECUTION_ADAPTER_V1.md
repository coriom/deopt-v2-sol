## Direct RPC collector and trust boundary

[`first_trade_live_state.py`](../tools/perps_v2_cutover/first_trade_live_state.py) obtains its own Base Sepolia RPC endpoint from the existing local testnet configuration without displaying it. Its method allowlist excludes public write methods. It checks chain ID 84532, latest block identity and age; probes EIP-1898 `blockHash`/`requireCanonical` support for `eth_call`, code and balance reads; and pins all state-dependent calls to that hash when supported. If the provider explicitly rejects hash-object parameters, it uses one block number and re-reads that block's canonical hash after collection, reporting the weaker mode. Missing/malformed RPC responses, unexpected runtime hashes, stale blocks and inconsistent block identity fail closed. Confirmed and pending executor nonces are recorded separately from pinned state. Coherent RPC results are **not** cryptographic proof of provider honesty; a future operator must use a trusted endpoint and compare independent evidence where necessary.

The collector checks the deployed PME and Engine runtime hashes, live PME domain separator, SEALED snapshot, reciprocal Engine wiring, PME/Risk Engine pointers, FMV2/Insurance/Vault authorizations, V1/OLD/NEW pause controls, Vault clearing ledger, market-1 funding/OI, registry existence/activity and 100-bps deviation, oracle mark availability, full buyer/seller position tuples and bilateral nonces. It records executor balance and EIP-1559 gas/priority quotes. When signed bytes are supplied, it asks the deployed OP GasPriceOracle for `getL1FeeUpperBound(uint256)` using the complete serialized byte length as a conservative size input and records the method/input; without signed bytes it reports no L1 quote rather than inventing one. The guard compares that quote with the separately approved local allowance. The local allowance does not cap eventual on-chain L1 charges. The collector reuses the verified executor-event inventory from block 47,619,181, verifies that baseline block hash, scans only subsequent PME `ExecutorSet` events and reconciles each known address with live mapping storage. It rejects an older-than-20,000-block baseline pending a new reviewed inventory.

The [sanitized live readback](../artifacts/perps_v2_first_trade_execution_adapter/live_readback.json) is pinned by EIP-1898 to Base Sepolia block **47,622,352**, hash `0xbcd3d6f46cc30e75c4e03b920eab666010309f811d7667bc07be1f93543f1214`. G1/G2 remain queued, PME_V1 and all OLD/V1 Engine maintenance flags remain active, clearing is **1,000,000,000** native mUSDC, and runtime-executor confirmed/pending nonces are **1/1**. It records the actual controls, inventory, fee inputs and `NOT_ARMED` reasons. Collection succeeds while maintenance is active; readiness is a distinct evaluation. Current missing rebind, permissions, selective unpause, sole-executor policy and signed-size L1 quote are expected conditions, not collector errors. ## Exact signed type-2 transaction and one-shot boundary

[`verify_type2_raw.cjs`](../tools/perps_v2_cutover/verify_type2_raw.cjs) uses the already-installed frontend `viem` library to parse a **signed EIP-1559 type-2** envelope from stdin, recover the actual sender, reserialize canonically and compute the Ethereum transaction hash from the exact input bytes. It rejects other types, contract creation, noncanonical encoding and nonempty access lists. [`first_trade_execution_adapter.py`](../tools/perps_v2_cutover/first_trade_execution_adapter.py) compares recovered sender, chain, PME destination, zero value, full calldata, nonce, gas limit and fee fields with the approved package and pinned collector result. It then invokes the existing guard for complete canonical trade ABI decoding/re-encoding, both trader signatures, reused PME domain, fresh intent ID, deadline, nonce, exact economic fields and close-only position limits. It additionally checks NEW_PMR 100-bps deviation against the pinned mark, Risk maxOracleDelay 600, clearing and old/V1 maintenance boundaries. No signed trade calldata is sent to a public RPC or placed in committed evidence.

The test-only integrated boundary is: approved package bytes/hash → collector → raw-envelope verification → exact trade guard → private execution lock → re-read package and collect/verify again → fsync `SUBMISSION_UNKNOWN` journal with the exact Keccak transaction hash → hand the **same immutable bytes** to a recording fake callback. The previous hash-only callback path was removed. A package edit, changed final nonce/state, duplicate journal, ambiguous prior submission or failed persistence prevents callback invocation. The callback result can only move the journal to `SUBMITTED`, never `CONFIRMED`; timeout retains `SUBMISSION_UNKNOWN` for manual tx-hash/receipt/nonce reconciliation. There is no operational send CLI, no signer, no public transport adapter, no retry, no replacement and no automatic maintenance release in this milestone. A future real sender needs its own separately approved implementation and operator authorization; it must preserve this exact-byte boundary and independently reconcile the canonical receipt and economic effects.

The [focused tests](../tools/perps_v2_cutover/test_first_trade_execution_adapter.py) use fake RPC and deterministic synthetic signers only. **26 tests passed** including the original 15 guard tests. They cover coherent hash-pinned reads, explicit block-number fallback, wrong chain/runtime, malformed output, changed canonical hash, stale block, pending nonce conflict, additional executor, exact signed type-2 acceptance, wrong signer/destination/nonce/calldata/fee, unapproved access list and other type, changed package/raw bytes, persistence failure, and duplicate/ambiguous journal. A synthetic raw transaction was decoded independently by Foundry `cast decode-transaction`; chain and target agreed with viem. The fake callback received only the exact verified bytes. These are local tests, not a trade simulation or public execution proof.
