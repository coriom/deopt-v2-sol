**Unset-token policy is a future operational gate.** New D3 storage reports `seizeConfigs(token) = (spreadBps=0, isEnabled=false, isSet=false)`. In `_discountBps`, the `isEnabled` field is consulted only when `isSet` is true; an unset token therefore gets zero Seizer spread and the collateral RiskModule weight. An arbitrary token does not thereby gain custody access: the planner queries the RiskModule for an enabled positive weight and, when computing a plan, requires Vault-supported collateral and balances (the base token is considered first; other tokens come from the Vault list). D3 exposes view-only plans and has no fund-moving function, Engine binding, or Vault transfer permission. A local test produced a view plan for an unset, Risk-enabled base token and then showed that only Timelock could explicitly disable that token, after which the plan was empty.

The source **does not enforce `isSet` before an Engine consumes a plan**. Operational safety therefore depends on a separate, verifiable go/no-go gate: before replacement Engine liquidation may be enabled, Timelock must set every intended token's Seizer policy, and operators must read back `seizeConfigs` (`isSet=true` and approved spread/enabled values), RiskModule weights, Vault supported-token configuration, and Engine liquidation maintenance state. The replacement Engine's `liquidate` path is gated by `onlyMigrationSealed` and `whenLiquidationNotPaused`; liquidation must remain paused until that future review completes. No Timelock configuration is prepared or authorized here.
